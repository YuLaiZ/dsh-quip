# Quip footer（俏皮话）

每轮回复完成后，用一次独立的已注册模型小调用生成一句拟人语气自评，作为小字渲染在该轮回复末尾，并以 plugin record 写入会话日志。

> 每条俏皮话都写进会话日志并带定位坐标（`seq` / `step` / `message.id` / `after`），生成记录面板展开后可按 `seq` 定位到会话文件里的那一行；生成记录按 500 条一个文件永久保存在本地，可在设置卡打开目录自行管理。

## 它做什么

- 监听会话事件流，在每轮回复完成（`turn/end`）后，把「用户这轮的发言全文 + 助手各步回复全文 + 工具按名称计次 + 耗时；可选带上本轮第一条和最后一条思考（全文）」交给一个独立的小模型调用，生成一句话，渲染在那轮回复的末尾。
- 这句话不出现在主模型的上下文里。
- 写入会话日志（plugin record，`ignorable` 标记，带 token usage）：重启后恢复，随 fork / 导出携带。record 的 data 与原生 `assistant/message` 同构，并用 `after` 钉回它所评论的那条回复（最后一条 `assistant/message` 的 `seq`/`message.id` 与 `turn/end` 的 `seq`）。
- 兜底句与模型生成的句子在 record 里可区分：前者的 `message.source.kind` 是插件自有 producer kind `dsh-quip`（不挂模型），后者是 `model` 并带 provider/model；`plugin.outcome` 另记模型调用的结局。
- 模型失败或被中止时不会展示半句俏皮话，结束原因与失败码随记录保存。

## 目前不能做什么

- **不进入 DSH 官方的 token 统计**。官方面板只统计主对话的模型调用；usage 在会话日志里，但官方面板不读它。

## 风格

| 风格 | 感觉 |
|------|------|
| playful 俏皮（默认） | 像干完活歪头邀功：「（叉腰）这波我自己都觉得很可以」 |
| hype 夸夸 | 热情吹捧本轮战绩 |
| roast 毒舌自嘲 | 温和地损自己，火力对准自己 |
| calm 冷静自评 | 工程师收工日志：「本轮定位到根因并修复，回归通过」 |
| custom 自定义 | 由你提供提示词，描述人设与语气 |

## 模型与降级

- 生成走 DSH 已注册的模型，设置卡下拉可选。
- 调用超时默认 120 秒，可在设置卡调整（5–600 秒）；`QUIP_TIMEOUT_MS` 优先。超时、失败时落到该风格的内置兜底池（可关）；模型判定素材不足时跳过。
- 每次生成的「结局」（ok / empty / timeout / aborted / error / skip / no-provider）和「来源」（model / fallback）分别记录，超时后兜底不会把超时原因盖掉。
- 请求层不设 maxTokens：长度只靠系统提示里的「不超过 N 字」约束。带思考的模型会把思考算进输出配额，硬上限会在正文出来前把生成截断。
- 素材默认脱敏（密钥与 token 模式替换为 `[redacted]`，可在设置卡关闭；关闭后原样进模型并明文写入生成记录），工具结果不进提示词；用户发言、回复正文与思考过程都不做字数截断。

## 生成记录

设置卡下方的「查看生成记录」可展开最近生成的素材（按脱敏开关）、系统提示词、输出原文、俏皮话模型自己的思考、token 用量（原样）、耗时明细、结局、结束原因与失败码、实际路由与思考等级、模型窗口、宿主与插件版本。面板每次展开都重新查询，标题行的「刷新记录」可手动刷新（加载失败时即重试）；列表只带各正文的字数，点开某条时才取完整记录并缓存。记录按 500 条一个文件永久保存在 `$DSH_HOME/quip/generations/`（文件名为该文件首条记录的时间），不再自动清理；面板上的「打开记录文件夹」可直接在系统文件管理器里打开该目录，删除文件即删除历史。面板只查最近 500 条，用户在目录里增删文件后再次打开面板即同步。

每条记录行显示所属文件名；展开后列出它在会话日志里的坐标（轮次、`seq`、虚拟步、`message.id`、所评论回复的 `seq`），并提供「复制定位命令」——一条 `zstd` + `jq` 命令，直接命中会话文件里那一行。

## 配置入口

设置页的「俏皮话」卡片，含模型下拉、生成超时（秒）与素材脱敏开关。修改后点保存即时生效。

## 诊断

`GET /api/quip/v1/health` 匿名可读，`persistence` 字段给出写入器来源（`host-probed` 为正常）、宿主与写入器 URL 的比对（`match`）、成功/失败计数与最近错误。写入失败时先看这里。
